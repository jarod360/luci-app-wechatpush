## 项目简介

**luci-app-wechatpush** 是一个 OpenWrt LuCI 网络监控与消息通知插件。本仓库是基于上游 [tty228/luci-app-wechatpush](https://github.com/tty228/luci-app-wechatpush) 持续维护的 fork，在保留原有通知和监控功能的基础上，进一步扩展了 QWRT 原生流量与在线检测、IP 归属地查询、设备事件合并推送及多项兼容性修复。

当前软件包版本：**3.6.20-14**

## 主要功能

- **网络状态通知**：检测路由器 IPv4/IPv6 地址变化，并推送网络状态。
- **终端设备监控**：检测局域网设备上线、离线，显示在线设备及相关信息；支持设备别名和 MAC 厂商信息。
- **设备事件合并推送**：同一轮检测发现的多台设备状态变化会合并为一条通知，减少设备集中上下线时的消息数量。
- **系统与主机监控**：监控路由器 CPU、温度及运行状态；可通过 SSH 获取远程主机（例如 PVE）的温度和磁盘信息。
- **安全通知与防护**：Web/SSH 登录提醒、失败登录自动封禁、黑名单转发流量拦截，以及端口敲门。
- **无人值守任务**：支持按设备在线状态、勿扰时段等条件执行配置的自动化任务。
- **多种通知渠道**：支持 Server 酱、Server 酱 3、PushPlus、WPUSH、WxPusher、企业微信、Telegram Bot、msmtp 邮件，以及自定义 API 模板。

## 本仓库的主要扩展

以下是相对于上游仓库的主要扩展和维护改动，具体行为以当前源码为准：

### IP 归属地查询扩展

- 登录提醒可查询 IP 地理位置。
- IPv4 支持配置本地 ip2region XDB 数据库作为优先查询来源，未命中时回退在线查询。
- 显示结果会进行层级归一化，不显示大洲、县区、运营商或 ASN。

### 企业微信 API 地址配置

- 可配置企业微信 API Base URL；留空时使用官方 API 地址。

### QWRT 原生功能

**QWRT 原生流量统计属于本仓库新增扩展。** 本仓库已移除原有依赖第三方插件的流量监控，避免其与科学上网等插件的兼容性冲突。当前流量监控仅通过新增的 QWRT 原生统计实现，包括累计流量、设备流量显示及每分钟流量增量告警；非兼容 QWRT 系统不提供旧插件流量监控回退。

仅适用于 **QWRT 2026.10.6 及以上版本**，在“基础设置”中分别启用：

- **QWRT 原生流量统计**：使用 `luci.client-rates get` 获取累计流量，供在线设备信息、设备通知、异常流量告警及无人值守低流量判断使用。该实现不再依赖或调用旧版 `wrtbwmon`。
- **QWRT 原生在线检测**：按 QWRT LuCI 概览使用的 ARP/MAC 规则判断设备在线状态，不发送 ping/arping 主动探测。该方式依赖当前 ARP 表，休眠设备或没有有效 ARP 记录的设备可能被判定为离线。

两个 QWRT 选项相互独立，默认关闭。非 QWRT 系统不要启用。

### TP-LINK 无线客户端辅助检测（3.6.20）

**本仓库新增扩展：** 可选接入 TP-LINK AC 路由器，按无线断开日志进行 30 秒离线确认，减少漫游误报和原检测等待，并提供在线客户端弹窗。

默认关闭，位于“基础设置 → QWRT 原生在线检测”下方。无需加入 Home Assistant，也不需要 SSH、修改 TP-LINK 配置或开启诊断功能。

1. 勾选“TP-LINK 路由器辅助检测”，填写 TP-LINK 的管理 IPv4 地址、用户名和密码。
2. 点击弹窗中的“保存并应用”。正常连接后显示绿色“无线客户端在线 N”。
3. 点击绿色数量按钮可查看名称、IP、MAC、所属 AP 和 SSID；手机窗口只显示名称、IP 地址和所属 AP。
4. 弹窗优先显示 WeChatPush 已保存的设备别名：MAC 匹配优先，IP 匹配其次，其次读取 QWRT 主机名和主在线设备表名称，最后使用 TP-LINK 名称；所有来源均无有效名称时显示“未命名”。不会回写 TP-LINK 备注。点击“刷新”只读取后台最新缓存，不重新登录 TP-LINK。

**最终检测规则：**

| 设备与状态 | 处理方式 |
| --- | --- |
| 已识别的 TP-LINK 无线设备，明确断开 | 从断开时间开始等待 30 秒；确认期结束后的一次成功采集仍确认离线，才进入离线推送，不再等待 QWRT 或 fork 原检测超时 |
| 等待期间重新接入、漫游成功，或当前客户端表显示在线 | 取消本次离线；生成推送内容前再复核一次 |
| 已识别无线设备的数据过期、请求失败、日志不可用或状态不明确 | 暂缓离线，不能把“查不到设备”直接当作离线 |
| 有线设备、未纳入 TP-LINK 辅助检测的设备 | 保留当前原检测方式及超时、次数设置 |
| 未启用辅助检测，或尚未成功识别无线设备 | 完全沿用原检测方式 |

辅助检测适用于 QWRT 原生检测开启和关闭两种情况，只接管已识别无线设备的离线确认；原有上线发现、通知开关、黑白名单、免打扰、事件合并和发送失败重试仍按原程序处理。不开启 QWRT 原生检测时，由 fork 原程序继续发现上线设备。TP-LINK 的客户端列表不会自动导入主在线设备列表，因此两处设备总数可能不同。

后台完成一轮采集后等待约 10 秒；超过 30 秒的缓存不能确认离线。首次读取最近 24 小时的无线日志，后续增量读取。30 秒是确认窗口，并非送达保证：实际推送还受采集周期、主程序扫描和消息通道影响，通常会晚于断开后 30 秒。断开超过 30 秒才恢复的设备仍可能收到离线通知。

状态说明：绿色为正常连接并显示当前无线在线数量；红色表示连接失败、账号密码错误、配置缺失或数据过期；橙色“不适配”表示管理 API 返回格式不兼容，并提示“**不适配您的TP-LINK设备，请联系ChatGPT协助开发。**”。灰色表示正在读取状态。状态框不再显示历史离线数量，避免与当前设备状态混淆。

已实机验证 **TP-LINK TL-R5005P-AC 1.0 / 固件 1.0.4 Build 260414** 与 **QWRT 25.12.2**。其他型号、固件和日志语言需要单独适配。当前使用局域网 HTTP 管理接口；凭据仅用于本地后台登录，状态缓存不含密码、Cookie 或登录令牌。轮询可能挤掉同一账号的 TP-LINK 网页管理会话。运行缓存位于 `/tmp`，重启后重新建立，停用辅助检测即可恢复原离线逻辑。

更多协议、异常处理和测试方法见 [TP-LINK 辅助检测说明](docs/tplink-assist.md)。

### 3.6.20 修复与维护

修订 **r3** 补充发送并发修复和名称回退：每次发送使用独立的权限 600 临时 JSON，避免设备、登录和定时通知相互覆盖，或被主循环清理；企业微信请求使用等价的 ASCII Unicode 转义传递中文、箭头和 emoji。并发回归测试在目标 QWRT 上验证了 12 条约 25KB 消息，网络发送使用测试桩。


- 修复 QWRT Bash/musl 下中文、箭头、emoji 的 UTF-8 字节读取问题，避免设备名称或流量排版偶发出现 `�`。
- 修复别名中 `%`、引号和 MAC/IP 前缀匹配问题，安全生成新设备 JSON。
- 无线断开与重新接入发生在同一秒时优先保留在线；日志读取失败不再使用旧断开记录确认离线。
- 避免残留 ARP 把 TP-LINK 已确认离线的设备改回在线；减少在线设备无变化时的重复写入。
- 企业微信通道说明更新；图文通道日志标记改为“【企业微信图文版】”。使用企业微信应用推送时，请使用稳定的企业微信代理，并在应用可信 IP 中配置该代理 API 的 IP 地址；若使用正向代理，则以实际公网出口 IP 为准。
- 新增协议、界面、两种检测模式、别名和 UTF-8 模板回归测试，构建及发布前自动验证。

### 离线检测参数与 MAC 名单

高级设置中的离线超时和检测次数用于控制设备离线确认。在“MAC 过滤模式一”中新增“离线自定义检测设备”模式；选择该模式后，下方显示“离线自定义检测列表” MAC 选择框：

- “离线超时仅针对推送设备”关闭时，所有设备都使用自定义超时和次数，包括选择了“离线自定义检测设备”模式的情况。
- 选择其他原有模式（包括“关闭”）时，完全沿用本 fork 原有的检测参数选择和推送过滤逻辑。
- 勾选“离线超时仅针对推送设备”并选择“离线自定义检测设备”模式后，名单内 MAC 使用高级设置中的自定义超时和次数；名单外、空名单或无法获取 MAC 的设备使用默认检测参数 **10 秒、2 次**。
- 该名单只选择检测参数，不改变设备的推送资格；实际通知仍遵循原有通知开关和过滤规则。

## 安装与依赖

软件包架构为 `all`。安装时由 OpenWrt 软件包管理器处理依赖。基础依赖：

- `iputils-arping`
- `curl`
- `jq`
- `bash`
- `lua`
- `luci-lua-runtime`

使用本仓库 GitHub Actions 构建产物时，下载对应的软件包后安装，例如：

```sh
opkg install ./luci-app-wechatpush_3.6.20-r14_all.ipk
```

从 r14 起，本仓库 CI 同时为 IPK 和 APK 写入独立修订号（如 `3.6.20-r14`），并在构建后核对 IPK 的真实版本和核心文件，避免旧版 LuCI SDK 忽略 `PKG_RELEASE` 导致同版本覆盖被跳过。升级时同时安装匹配的中文语言包。已有自定义配置、别名和图片路径继续保留。

可选依赖：

- **本地/远程磁盘信息**：`lsblk`、`smartmontools`、`smartmontools-drivedb`。
- **远程主机信息**：`openssh-client`、`openssh-keygen`，并提前配置 SSH 密钥登录。
- **邮件通知**：安装并配置 `msmtp`；也可在插件的邮件配置项中填写 SMTP 参数。

本仓库当前 GitHub Actions 工作流分别使用 OpenWrt 23.05.3 SDK 构建 IPK、OpenWrt 25.12.0-rc1 SDK 构建 APK，构建目标为 x86/64。软件包本身为架构无关包，但上述 CI 产物不代表已提供 QWRT ipq53xx/aarch64 专用构建；其他目标平台请使用对应 SDK 自行编译。

## 使用说明

- 首次安装或升级前，可先执行 `opkg update` 更新软件包索引。
- 在 LuCI 的“服务 / 微信推送”页面选择通知方式并填写对应凭据，再启用服务。
- 使用企业微信时，可信 IP 白名单仍由企业微信管理后台控制；如配置正向代理，应放行代理服务器的公网出口 IP。
- 启用 QWRT 原生流量或在线检测前，请确认设备运行的是 QWRT 2026.10.6 或更新版本。
- 本地 ip2region 数据库需自行准备有效的 IPv4 XDB 文件，并在基础设置中填写实际路径。

## 故障排查

提交问题时请附上设备型号、系统版本、软件包版本，以及相关日志。可在路由器上执行：

```sh
/usr/share/wechatpush/wechatpush
bash -x /usr/share/wechatpush/wechatpush t1
```

同时提供 `/tmp/wechatpush/` 中与问题相关的日志或调试文件。请勿在公开 issue 中粘贴企业微信 Secret、Bot Token、邮箱密码等敏感凭据。

### 登录提醒与免刷屏（r8）

登录白名单内 IP 免自动封禁，是否推送仍由已启用的登录事件和“登录提醒免打扰”模式决定：

- **关闭**：符合条件的每次登录事件正常推送。
- **仅记录到日志**：不推送，记录每次符合条件的事件，包括白名单 IP；日志总开关仍生效。
- **仅在首次登录时推送通知**：首次成功发送后，同一 IP 在设定秒数内不重复推送，重复登录不延长窗口；到期后再次登录可推送。Web 与 SSH 共用同一 IP 的窗口。
- **登录提醒日志免刷屏**：只在首次登录推送模式下显示和生效；首次事件仍记录，窗口内重复事件不记录。关闭此项则重复事件仍记日志，但不会因此重复推送。

免打扰计时不再读取日志，关闭、清空、轮转日志均不改变窗口；通知发送失败或被全局免打扰拦截时不开始计时。独立状态保存在 `/tmp/wechatpush/login_notice_times.json`，最多保留 256 个 IP，权限 600，设备重启后清空。失败登录计数、封禁阈值和白名单免封禁规则保留。

修订 **r9**：TP-LINK 在线客户端弹窗在 TP-LINK 未提供有效 IPv4 地址时，按 MAC 匹配 QWRT 在线设备表，再尝试唯一的主机提示地址；不会使用离线设备记录补全，不覆盖 TP-LINK 已提供的有效 IP。补全后的地址也用于 IP 别名匹配；仅影响显示，不增加轮询或修改在线判定。

修订 **r10**：原在线设备列表增加别名优先、QWRT 主机提示和已保存名称回退；自动名称去除末尾 `.lan`，无有效名称显示“未命名”。后台常规扫描批量读取一次主机提示，并修复 TP-LINK 已管理在线设备提前返回、漏掉后续名称刷新的问题；不在快速检测轮次重复读取主机提示，不改变在线判定。内部 `unknown` 状态仍保留原含义。

### 旧 Bash 的 UTF-8 边界兼容（r11）

目标 QWRT 的 Bash 5.1.4 在 UTF-8 命令替换输出跨越 512 字节缓冲区边界时可损坏字符；GNU 官方补丁 [bash51-014](https://ftp.gnu.org/gnu/bash/bash-5.1-patches/bash51-014) 修复了这类问题。已在目标路由器用原模式复现，并验证应用内兼容处理后，5 个独立进程的 810 次边界比对通过。

WeChatPush 启动时保留原语言选择，再将自身及子进程的字符处理模式固定为 `LC_ALL=C`；中文内容仍由 Lua/JSON 按 UTF-8 处理，不修改系统全局语言或 Bash 程序。后台结果读取改用字面量赋值，避免把设备清单重新解析成 Shell 代码。


### 推送封面调整（r12）

默认封面更新为已在微信客户端确认显示效果的“实时提醒”图片，尺寸 1068×455，约 29.7 KB，无可见水印。仓库仅保留 `logo.jpg`；自定义图片路径继续使用用户配置。尺寸提示区分 news 推荐的大图 1068×455、小图 150×150 与本通道使用的 mpnews，提醒客户端可能裁切，文字和图标应集中并保留边距。
